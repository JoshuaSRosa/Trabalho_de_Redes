================================================================================
1.3. JOGO MULTIPLAYER (opção escolhida)
================================================================================

- permitir que jogadores se conectem
  → servidor/main.py (accept loop + threads por sessão)
  → cliente/main.py (socket.connect)

- permitir a criação ou entrada em uma partida
  → cliente/main.py: envia {"tipo": "fila", "melhor_de": N} ao conectar
  → servidor/main.py roteador_sessao: intercepta FILA → matchmaking.entrar()
  → servidor/matchmaking.py: fila por melhor_de (1, 3, 5)

- gerenciar os jogadores participantes
  → servidor/sessoes.py: classe Sessao (conn, addr, filas, partida, viva)
  → servidor/partida.py: por_label = {"P1": s1, "P2": s2}

- controlar o estado da partida
  → servidor/jogo.py: PARTIDA_MD (série MD-n), JOGO_DA_VELHA (rodada)
  → servidor/partida.py: snapshot(md) → mensagem STATE

- transmitir as ações dos jogadores
  → servidor/rede.py: receber_linha, enviar
  → servidor/partida.py: avisar_ambos(s1, s2, obj)

- validar as ações realizadas
  → servidor/jogo.py JOGO_DA_VELHA.inserir_jogada: valida turno, limites,
    casa ocupada, partida encerrada
  → servidor/jogo.py PARTIDA_MD.inserir_jogada: valida série encerrada

- impedir ações inválidas
  → servidor/jogo.py: ValueError com mensagem específica
  → servidor/partida.py: captura ValueError → envia {"tipo": "erro"}
  → cliente/estado.py: trata erro → reativa o prompt para nova tentativa

- manter os participantes sincronizados
  → servidor/partida.py: avisar_ambos em cada jogada válida (STATE)
  → cliente/estado.py: atualiza estado local
  → cliente/ui_terminal.py: renderiza board atualizado

- detectar o término da partida
  → servidor/jogo.py JOGO_DA_VELHA: linha/coluna/diagonal/cheio →
    self.encerrada = True, self.vencedor definido
  → servidor/jogo.py PARTIDA_MD: vitorias_necessarias ou melhorD rodadas
    → self.finished = True, self.winner definido
  → servidor/partida.py: verifica partida_antes.encerrada → RODADA_FIM

- informar o resultado
  → servidor/partida.py: RODADA_FIM (resultado da rodada) + FIM (resultado
    da série)
  → cliente/ui_terminal.py: renderização colorida com tabuleiro final

- permitir o início de novas partidas
  → servidor/jogo.py PARTIDA_MD.iniciar_proxima_partida(): nova rodada
    automática da série (alterna quem começa via 'quem_comeca')
  → Para nova SÉRIE: cliente reconecta (limitação; ver "Limitações")

================================================================================
4. REQUISITOS MÍNIMOS
================================================================================

- utilizar sockets
  → servidor/rede.py, cliente/rede.py
  → socket.AF_INET + socket.SOCK_STREAM (TCP nativo, sem frameworks)

- permitir comunicação entre múltiplos participantes
  → servidor/main.py: threads por cliente (leitura + escrita + roteador)
  → servidor/matchmaking.py: filas paralelas por melhor_de
  → servidor/partida.py: thread por partida → N partidas simultâneas

- definir e implementar protocolo de aplicação próprio
  → comum/protocolo.py: constantes de tipo e campos
  → PROTOCOLO.md: especificação completa (entregável 5.2)
  → JSON delimitado por '\n' sobre TCP

- tratar mensagens ou requisições inválidas
  → servidor/main.py roteador_sessao: responde {"tipo": "erro"} para tipo
    desconhecido quando sessão está fora de partida
  → servidor/partida.py: valida presença de linha/coluna → {"tipo": "erro"}
  → servidor/jogo.py: validação semântica (ValueError)
  → cliente/main.py thread_recebimento: captura JSONDecodeError e
    UnicodeDecodeError
  → LIMITAÇÃO: thread_leitura do servidor NÃO captura JSONDecodeError
    (apenas OSError). JSON malformado derruba a sessão, mas não o servidor.

- tratar desconexões e falhas de comunicação
  → servidor/sessoes.py Sessao.encerrar(): sentinela None em fila_entrada,
    fila_partida e fila_saida → destrava consumidores
  → servidor/partida.py: get(timeout=1) + checagem viva=False detecta
    queda brusca (kill -9, cabo puxado) em até 1s
  → servidor/partida.py: envia DESCONECTOU ao sobrevivente
  → cliente/main.py main(): shutdown + join(timeout=2) + close no finally
  → cliente/ui_terminal.py: renderiza DESCONECTOU
  → LIMITAÇÃO: reconexão não implementada (ver "Limitações")

- utilizar mecanismos de concorrência ou multiplexação
  → servidor/main.py: 3 threads por sessão (leitura, escrita, roteador)
  → servidor/partida.py: 1 thread por partida
  → servidor/matchmaking.py: threading.Lock em filas de pareamento
  → servidor/sessoes.py: queue.Queue (fila_entrada, fila_partida, fila_saida)
  → cliente/main.py: thread_recebimento + thread principal com threading.Event

- implementar corretamente as regras e o estado
  → servidor/jogo.py: PARTIDA_MD e JOGO_DA_VELHA (bloco de teste comentado
    valida séries MD1/MD3/MD5 isoladamente)
  → Bateria de testes de integração: MD1, MD3, MD5, empates, desistência

  → coberto acima

  → coberto acima (threads + queues)

  → TCP exclusivamente

================================================================================
LIMITAÇÕES CONHECIDAS (não implementadas — documentar no README)
================================================================================

- Reconexão de jogador após desconexão
  → Não implementada. O enunciado exige "tratamento de desconexão" (detecção
    + notificação + encerramento limpo — cumprido). Reconexão persistente
    (retomar partida após reconectar) é funcionalidade ADICIONAL, planejada
    na proposta inicial, não implementada por priorização de tempo.

- Tolerância a falha do servidor (persistência de estado)
  → Fora do escopo. Estado em memória; queda do servidor encerra partidas
    em andamento.

- Interface gráfica
  → Interface via terminal com cores ANSI. Permitido pelo enunciado
    ("complexidade da interface não será o foco da avaliação").

- JSON malformado no servidor
  → thread_leitura captura apenas OSError, não JSONDecodeError.
    Cliente malicioso/bugado pode derrubar a própria sessão, mas não o
    servidor (thread morre isolada; demais sessões continuam).

- Nova série sem reconectar
  → Após FIM, o cliente encerra a conexão. Para jogar nova série, é
    necessário reabrir o cliente.
